# Static design site for approval (Vercel)

The owners' team confirmed that Phase 1 is a design phase: the goal is an approved design, and the platform (Vercel or WordPress) does not matter yet. So the approved design is a **static HTML/CSS/JS site in `site/`, deployed on Vercel**. The WordPress theme in `frontend/` stays as the Stage 2 reference. Everything here is a **[Proposal]** for the owners to accept or change.

**Design read:** a direct-booking site for tired, mobile-first travellers near an airport; calm airport-wayfinding language; static HTML/CSS with one tiny script. Dials: variance 5, motion 3, density 4. Cross-checked with the design skills: Atkinson Hyperlegible and a minimalist/Swiss style fit; a three-step funnel with a progress indicator fits the booking flow; our own palette stays (no stock blue and orange).

## Rules that apply to every page

- **Preview honesty.** A thin strip at the top of every page reads `Design preview. Photos, prices and details are samples.` Every page has `<meta name="robots" content="noindex">` and Vercel sends `X-Robots-Tag: noindex`. The booking flow never collects real data: no network calls, no card fields (the payment step is a labelled placeholder), nothing stored. Sample prices live only in `data/homes.json` with `"sample": true`.
- **Light and fast.** No framework, no build dependency (`node build.mjs`, zero npm packages), no third-party requests (links out to wa.me and maps are fine, nothing loads from them), no images (photo slots are CSS panels with fixed aspect ratio, ready for real `<img width height loading="lazy">`), no icon library (CSS-only chevrons). Budgets per page: HTML at most 16 KB, shared CSS at most 22 KB, shared JS at most 5 KB (raw, all pages together share the same files). Two fonts only (Archivo wide 700, Atkinson Hyperlegible 400 and 700), both self-hosted woff2 from `frontend/luton-homes/assets/fonts/` copied to `site/public/fonts/` with the two OFL files; preload only the two used above the fold; `font-display: swap`.
- **Tokens (unchanged).** ink `#0F2F3A`, ink-2 `#1B4452`, paper `#F3F6F5`, white, sky `#D8E7EB`, slate `#51666E`, amber `#F2B01E` (primary buttons only). Light theme only (`color-scheme: light`); dark mode is a later decision. 4px radius everywhere, no shadows, one 1px border `rgba(15,47,58,.15)`. Spacing scale 4/8/16/24/32/48/72/96. Type scale 14.4/18/22.5/28/35 and a fluid h1. Headlines Archivo (wide), body Atkinson 18px/1.6, line length at most 62ch. Left aligned. Sentence case. No all-caps labels, no eyebrow labels above headings, no numbered markers, no decorative dots, no scroll cues, no version stamps.
- **Copy.** Plain verbs, no filler (no "elevate", "seamless", "unleash"). **Never write an em dash or en dash** (use a full stop, comma or colon; ranges use a hyphen). Do not state facts the owners have not given: use only what is known (five homes, 34 Beaconsfield, Luton LU2 0RW, Luton Airport nearby, WhatsApp 07934 586612 as the chat number, direct booking). Distances, bed counts, amenities, rules and prices are samples and are shown only inside the preview. No fake testimonials, no fake ratings, no fake counters.
- **Quality bar.** WCAG 2.1 AA contrast, visible focus (3px ink ring with 2px white offset; amber ring on ink), skip link to `main#content`, one `h1` per page, ordered headings, landmarks with names, 44px tap targets, labelled form fields with errors beside the field (`role="alert"` text, never colour alone), no horizontal scroll at 375px, `prefers-reduced-motion` respected, `touch-action: manipulation`. Motion: one hero load reveal (opacity and a 12px rise, 400ms, staggered 60ms, transform and opacity only), hover and focus colour changes, and a cross-page `@view-transition { navigation: auto; }`. No scroll listeners, no parallax, no marquee.
- **Reusable devices.** The boarding-pass search card (notched edges) from the home spec. A **gate sign** photo slot per home: a deep-ink or sky panel showing the home's monogram in large Archivo (`ES`, `LL`, `ESS`, `GS`, `GN` for EasyStay, Luton Lodge, EasyStay Studio, The Garden Studio, The Garden Nest) and the text `Photo coming soon` small beneath it; fixed `aspect-ratio` so real photos drop in without layout shift. Tonal variants cycle sky, paper-dark and ink-2.

## Files

```
site/
  build.mjs            node build.mjs -> dist/ (no dependencies; Node 22)
  vercel.json          outputDirectory dist, buildCommand "node build.mjs", cleanUrls, trailingSlash true, headers: X-Robots-Tag noindex, long cache for /fonts and /assets, X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin
  data/homes.json      five homes: slug, name, monogram, tone, sample facts (sleeps, beds, distance text, nightly rate in GBP, one-sentence summary, amenities[], rules[]), all with "sample": true
  src/partials/{head,header,footer,preview-strip}.html
  src/pages/*.html     index, homes (list), home-template (one per home), about, contact, faq, 404, book (flow), book-confirmed
  src/styles.css, src/app.js
  public/fonts/*       3 woff2 + 2 OFL texts, robots.txt (Disallow: /)
  tests/check.mjs      static checks (see Tests)
```

`build.mjs` replaces `{{key}}` and `{{> partial}}` in the templates, writes one folder per route (`dist/homes/easystay/index.html`), copies `public/` and the two source assets (hash not required). Keep it under 120 lines.

## Pages

1. **Home** (`/`). Header (wordmark, `Homes`, `How booking works`, `Contact`, amber `Message us on WhatsApp`; on phones the button shortens to `WhatsApp` and the nav wraps below, as in the WordPress theme). Hero (ink): h1 `Homes near Luton Airport, booked direct`, one sentence, the boarding-pass card (check in, check out, guests, button `Check availability`). Submitting goes to `/homes/?in=...&out=...&guests=...` (same validation as the WordPress card: check out after check in, no past check-in, whole number of guests, inline errors); no JS: the button links to `/homes/`. Then, each a different layout family: **Homes** (asymmetric six-column grid: two large gate-sign tiles then three smaller, each with name, `by Luton Homes`, one fact line and `From £{rate} a night` styled as sample; whole tile is one link); **Why book direct** (stacked rows: bold lead left, one sentence right, hairline between, not cards: `Talk to a person`, `Clear check-in details`, `Pay securely online`); **How booking works** (a horizontal line of three verbs on desktop, vertical on phones: `Pick your dates`, `Choose a home`, `Pay securely`, each with one short sentence); **Find us** (address, a `Get directions` link to `https://www.google.com/maps/search/?api=1&query=34+Beaconsfield+Luton+LU2+0RW`, a WhatsApp link; no embedded map); **Contact band** (ink) and footer (name, canonical description `Short-stay homes near Luton Airport. Five properties, one team. Book direct with Luton Homes.`, address, year).
2. **Homes** (`/homes/`): h1 `Our homes`; if `in`, `out`, `guests` are in the URL show a summary bar (`12 Nov 2026 to 15 Nov 2026, 2 guests`, `Change dates` link) and an estimate line on each card (`3 nights from £{rate x nights}`, labelled `Estimate from sample rates`); otherwise the five cards. Cards carry the dates onward in the link query.
3. **A home** (`/homes/{slug}/`, five pages from one template): h1 name; a three-slot gate-sign gallery (one large, two small, `aspect-ratio` fixed); facts row (sleeps, beds, distance to airport: sample); summary and a two-paragraph description (sample, generic); amenities (two-column list); house rules (list); a `Location` block (address, directions link); a sticky **booking panel** on desktop (right column) and a sticky bottom bar on phones that scrolls to the panel: check in, check out, guests, nightly estimate (`£{rate} x {n} nights = £{total}`, labelled sample), amber `Reserve`, text link `Ask about {Name} on WhatsApp`; `Other homes` row linking the other four. `Reserve` goes to `/book/?home={slug}&in=..&out=..&guests=..`.
4. **Book** (`/book/`): three steps on one page with a progress indicator (`Your details`, `Review`, `Pay`; `aria-current="step"`, back and next buttons, focus moves to the step heading). Step 1: name, email, phone, arrival note (labelled, `autocomplete`, inline validation on blur). Step 2: summary card (home, dates, guests, nightly breakdown, total, all labelled sample) and the cancellation text `Cancellation terms to be confirmed.`. Step 3: a clearly labelled placeholder box `Secure card payment will appear here once a payment provider is connected.` and a button `Complete preview booking`. Without JavaScript all three steps stack. Nothing is sent or stored. A permanent notice sits above the form: `This is a design preview. No booking is made and nothing you type is saved or sent.`
5. **Confirmed** (`/book/confirmed/`): h1 `Booking confirmed (preview)`, reference `LH-SAMPLE`, the summary from the URL, what happens next (check-in details by message), WhatsApp link.
6. **About** (`/about/`), **Contact** (`/contact/`: WhatsApp, address, directions; no contact form), **FAQ** (`/faq/`: `<details>` list of six questions with short sample answers: how to book, can I ask first, how do I pay, what happens after I book, can I change dates, where are you), **404**. Footer links to these pages. Legal pages (privacy, cookies, terms) are out of scope until the owners supply the text; the footer does not link to them.

## app.js (at most 5 KB, no dependencies)

Date helpers (valid date, past check, format `12 Nov 2026` with fixed month names), the search card submit handler, reading `in/out/guests/home` from the query string, nights and estimate calculation (rates from a small inline JSON in each page or a `data-rate` attribute), the booking step controller and validation, `min` on date inputs. Guard each feature by `if (el)`. Export the pure helpers with `module.exports` guard for Node tests.

## Tests (`site/tests/check.mjs`, plain Node, run after build)

Fail with one message per problem and exit non-zero: every internal `href`/`src` in `dist` resolves to a file; each page has a `<title>`, a meta description, `noindex`, exactly one `<h1>`, a `main#content`, and the preview strip; no `—` or `–` characters in any page, CSS or JS; no `http(s)://` origin in `src`/`href` of loaded resources except wa.me and google.com/maps links in anchors; no `<img>` without `width` and `height`; byte budgets from above; `robots.txt` and `vercel.json` headers contain noindex; the home page has the canonical description verbatim; `app.js` helper unit checks (valid and invalid dates, past dates, nights, estimate, guest parsing). `package.json` has `"type": "module"` and a `test` script, no dependencies.
